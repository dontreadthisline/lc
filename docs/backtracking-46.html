执行日志

选择 / 递归 / 撤销：对共享状态的增量维护与复原

状态分两类：path（append 传参版无需回退）和 used（共享数组必须回退）。判断标准就一条：这个状态的修改发生在哪一帧、谁还会读它。
  1. 选择：used[i] = true + 把 append(path, i) 的新 header 传下去。append 结果直接当实参时，本帧 path 变量从未被赋值 —— 所以 path 不需要显式回退（这正是 437 树遍历不需要撤销的机制）。
  2. 递归：带着共享的 used 和新的 path 视图深入，让下一层在「i 已占用」的世界里做选择。
  3. 撤销：used[i] = false。used 的底层数组全局只有一份，本帧 for 的下一个候选要读它 —— 不复原就是公共财产被永久侵占。
path 与 used 的不对称不是玄学：path 的"长度视图"每帧私有（值传递），used 的底层数组全体共享（引用语义）。回退义务跟共享走，不跟参数走。

实验：忘掉 used 的复原（勾选「忘撤销对照」）

症状：只输出 1 个结果（字典序第一个）。不报错、不死循环，安静地错。

机理：第一条路径走完后 used 全 true；每个栈帧的 for 里所有候选在准入判断处被跳过，候选全部枯死。对照动画里第二棵树只剩一条孤路。

为什么不重不漏

  • 不重：排列 —— used 剪掉重复；组合 —— 递增剪掉同一集合的所有降序写法。每个答案对应树上唯一一条根到叶路径。
  • 不漏：for 枚举全部候选；撤销保证每个候选开局时世界一致。

组合树 = 排列树 + 升序规范化剪枝

组合是集合，集合无序；在决策树里表示它必须约定规范写法 —— 升序。同一集合的 k! 种排列写法，只保留升序那一条代表路径。这就是 C(n,k) = P(n,k)/k! 的字面意思。 
n=4, k=2 两棵树:

   排列树: 每层任选未用过的              组合树: 只准选比上一项大
   12 条路径 = P(4,2)                   6 条路径 = C(4,2)

   root                                  root
   ├─1─┬─2 [1,2]                         ├─1─┬─2 [1,2]
   │   ├─3 [1,3]                         │   ├─3 [1,3]
   │   └─4 [1,4]                         │   └─4 [1,4]
   ├─2─┬─1 [2,1] ←同{1,2}!               ├─2─┬─3 [2,3]
   │   ├─3 [2,3]                         │   └─4 [2,4]
   │   └─4 [2,4]                         └─3───4 [3,4]
   ├─3─┬─1 [3,1] ←同{1,3}!
   │   ├─2 [3,2] ←同{2,3}!
   │   └─4 [3,4]
   └─4─┬─1 [4,1] ←同{1,4}!
       ├─2 [4,2] ←同{2,4}!
       └─3 [4,3] ←同{3,4}!

组合模式动画里的红色虚边（带 ×）就是左边被剪掉的那些降序边：节点 [2] 的候选 1、节点 [3] 的候选 1 和 2、节点 [4] 的候选 1、2、3 —— 分布恰好是「下三角」。每个终集合的 k! 条排列路只剩升序一条。

  • start 哨兵：入口 backtrack(0, [])，0 不在值域 —— 它的身份是「假想的上一项」，表示空集。链表 dummy 节点、前缀和 preSum[0]=0 都是同一技巧：用值域外的占位表示空状态。
  • used 在组合里冗余：递增保证 i 永远往前走，同一值不可能重复入选。留着无害（每帧 O(n) 扫描的常数），去掉更诚实。
  • 78 子集 = 这棵树的所有节点：组合只收固定深度 k 的叶子，子集每个节点都收 —— 同一个递增引擎，一处收获条件的差别。

解空间图：同一组元素张成的两种图

决策树的节点是路径（所以有 n! 个节点）；解空间图的节点是元素本身（永远只有 n 个）。图上的一条路径才是一个候选解。回溯 = 在解空间图上 DFS 枚举满足约束的路径。

排列 = 无向完全图 Kn（哈密顿路径枚举）

任何元素可接任何元素（边无向）→重访诱惑存在 → 需要 visited 执法「每点恰一次」。哈密顿路径数 = 4! = 24。

组合/子集 = 递增 DAG（有向路径枚举）

边只从小的指向大的（i→j 仅当 i<j）→方向天然禁止回头 → 不需要 visited。k 节点路径 = C(4,k)；任意长度 = 2⁴ = 16。

免撤销的严格证明 —— 裁环论证

正确命题: v 被宣判死时, 不存在任何「需要经过 v 的简单成功路径」 —— v 死得清白。
核心在「邻居是祖先」那一栏: 经祖先的成功路径必带环, 裁掉环段后它不再经过 v —— 那种成功不需要 v, v 错过它无妨。这就是裁环桥的严格形态。

79 网格图: 同一格子在不同历史里两副面孔

看 (1,1) 的出边 —— 同一格、同进度(w2), 仅历史不同:

出边F2 历史(栈={(0,0),(0,1),(1,1)})S 历史(栈={(0,0),(1,0),(1,1)})
(0,1)在栈上(祖先) → 禁走白 → 可走, 通向成功!
(1,0)白, 匹配 w3(B) → 走后死在栈上(祖先) → 禁走
(1,2)白, 不匹配 w3 → 滤白, 不匹配 w3 → 滤

结论: (1,1) 在 F2 里死, 在 S 里活 —— 同一格子的「白/祖先」身份随历史翻转。更致命的: S 走 (1,1)→(0,1) 时, (0,1) 在 S 里不是祖先(它是 F2 的祖先!) —— 这不是回边, 没有环, 裁无可裁。第一次探索的失败只对那条历史有效。

分界一句话: 127 判定版只活一条历史 —— 节点前途在唯一一次探索中被穷尽(出边静态 + 被滤边只指向真祖先，裁环罩得住)。79 的约束使第一次探索的失败只对那条历史有效 —— 要试新历史就必须归还旧历史占用的格子，这就是撤销。

79 为什么没有裁环桥

S 路径 = (0,0)A→(1,0)B→(1,1)A→(0,1)B→(0,2)A = ABABA。试着「裁掉」中途的 (1,1):

裁掉后剩余字符序列 ABBA ≠ ABABA(第3位错位), 且 (1,0) 与 (0,1) 不相邻, 路径本身断裂。匹配进度依赖路径形状 —— 裁剪破坏一切。所以 79 的格子死不能升级为全局死, 必须撤销归还。

探索 v 时邻居 w 的状态处置「经 v→w 的成功路径」为何不需要担心
未标记(白)递归探索归纳: 成功则已 found; 失败则 w 死(不存在经 w 的简单成功路径)
在栈上(v 的祖先)跳过经它的路径必带环 → 裁掉环段 → 成功路径不再经过 v(它不需要 v)
已死(墓碑)跳过归纳: 不存在经 w 的简单成功路径
结论: 三方向都堵死 → 不存在需要 v 的简单成功路径 → v 死得清白 → 永久 visited 不损害「存在成功路径 ⟺ found」。每个节点唯一一次探索, 足以代表全人类。
