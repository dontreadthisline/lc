# 家族 4：二分与值域搜索 —— 专题讲解

## 0. 速查卡（复习用）

- **信号**：有序数组找值/找边界；"最小化最大值/最小速度/最低载重"型；答案落在可枚举值域且判定单调
- **原语**：`lowerBound(x)`（第一个 ≥x，二选一收敛式）、三分支查值（704）、二分答案（值域+单调谓词）
- **锚点**：锚点问题（猜大了还是小了）→ 模板三分支还是二选一 → 哨兵保证值域良定义 → `l+(r-l)/2` 防溢出
- **失效**：无单调性（先造单调：旋转认半、值域换元），有重复元素的旋转数组需缩边

## 1. 识别与反识别

**正信号**：O(log n) 的要求（n 大或明说）；"最小化最大值"；答案本身是数值且可行与否可 O(n) 判定。

**负样本对照**：

| 对比 | 分野 |
|---|---|
| 704/34 vs 33 | 数组现成有序 → 直接查；旋转过 → 先认出哪半有序再查（局部有序） |
| 875/1011 vs 704 | 搜索空间是**答案值域**（速度/载重），不是下标——题面出现"最小 k 使得…"，二分答案 |
| 378 vs 875 | 判定从值比较升级为**计数谓词**（矩阵里 ≤ mid 的个数是否 ≥ k）——骨架同款，谓词自己写 |
| 162 vs 33 | 邻居比较定方向（结构判定）vs 值域判定——"任何峰都行"是结构谓词 |

## 2. 入门讲解：三个层次，一套骨架

**层次一：查值（704）**。闭区间 `[l,r]` 三分支，不变量一句话：**"答案若存在，必在 [l,r] 里"**。命中返回、大了砍右、小了砍左，区间缩空即不存在。

**层次二：查边界（34）**。命中后不停——左边界 = 第一个 `≥ target` 的位置（lowerBound）。模板从三分支变**二选一**：`nums[mid] >= x → r = mid`（mid 可能就是答案，不能丢）；`< x → l = mid + 1`（mid 绝不是答案，放心丢）。右边界 = `lowerBound(target+1) − 1`，一个函数跑两遍免费拿到。

**层次三：二分答案（875/1011/378/410）**。搜索空间不再由数组提供，是你自己圈的值域 `[1, max]`；判定函数自己写（吃完要几小时 / 几天运完 / 计数 ≥k），要求**单调**（k 越大越容易满足）。骨架与层次二完全同源：找"第一个可行的 k"。

**33 旋转数组**：整体无序，但 mid 一刀切下**必有一半有序**（断点只有一个）。先认出有序的那半（`nums[mid] >= nums[l]` ⟺ 左半有序，需元素互异），target 落在其值域内 → 进那半；否则去另一半。

## 3. 原语库

| 原语 | 签名 | 前置条件 | 复杂度 |
|---|---|---|---|
| 三分支查值 | 闭区间 `[l,r]`，命中即返 | 数组有序（或局部有序已判定） | O(log n) |
| `lowerBound(nums, x)` | 返回第一个 ≥x 的下标；全 <x 返回 len | 数组非降 | O(log n) |
| `upperBound` | `lowerBound(x+1) − 1`（最后一个 ≤x/==x） | 同上 | O(log n) |
| 二分答案 | 值域 [lo,hi] + 单调谓词 meet(v) → 最小可行 v | 谓词单调（可行 ⟹ 更大皆可行）；哨兵保证 hi 侧存在可行（或 lo 侧存在不可行） | O((值域宽 + meet 代价)·log) |
| 计数谓词（378 型） | meet(v) = 数 ≤v 的个数 ≥ k | 结构上可 O(n) 计数 | O(n log V) |

标准库对照：`sort.Search(n, f)` 就是 lowerBound 的泛化（f 单调布尔），见 `lc_tests/slices_binary_demo_test.go`。

## 5. 数学形式化

**单调谓词定理**。

- **命题**：谓词 P 在有序域上满足 $P(v) \Rightarrow P(v{+}1)$，则域被切成 $[\text{不可行} \mid \text{可行}]$ 两段，lowerBound 恰返回分界点（第一个可行）
- **证明**：对二选一循环的不变量归纳——任意时刻 `[l,r)` 含分界点；每轮区间严格缩小（`r=mid < r` 或 `l=mid+1 > l`，左中点保证前者不越界）；终止时 `l==r` 即分界 ∎
- **假设**：P 单调；区间内两侧各有点（哨兵）
- **反例**：不单调的 P（如满足条件的数据呈孤立带）——二分可能跳过可行解；33 带重复元素时"哪半有序"不再可判定，须缩边破坏重复

**旋转数组的判定引理**。

- **命题**（元素互异）：`nums[mid] >= nums[l]` ⟺ `[l, mid]` 有序
- **证明**：逆否——左半含断点则 `nums[l] > nums[mid]`（断点右侧整体小于左侧最小值…由互异性严格化）∎
- **反例**：`[1,0,1,1,1]`，`l=mid=0` 时 `nums[mid]==nums[l]` 但左半无序——重复破坏等价性

**二分答案的复杂度**：值域宽 W、判定代价 O(n) → O(n log W)。875 的判定 `(pile+k-1)/k` 是向上取整的整数除法原语。

**004 切分法**（本族终极形态）：两个有序数组的第 k 小 = 猜"nums1 贡献 i 个"，两个交叉检查判定拿多/拿少，±∞ 哨兵处理越界——完整推导见 `lc/004.go` 的 `FindMedianBinarySearchAlgs` 注释（锚点问题的现场教学）。

## 7. 深挖篇：实战翻车与分界知识

### 7.1 本仓库实证翻车（三连坑，均实际发生）

**坑 1：`i < j` vs `i <= j` ——同一个错误犯三次后的结论：永远 `i <= j`。**
错在把"区间还有没有元素"和"区间还能不能收缩"混为一谈。正确的心智模型是**循环不变量承诺**：

```
承诺: 答案（若存在）始终 ∈ [lo, hi]
每轮: mid 判决后, 砍掉确定不含答案的一半, 收缩保承诺
终止: lo > hi ⟺ 区间空 ⟺ 承诺无法维持 ⟹ 不存在 / lo 即边界
```

写成 `i < j` 时，区间剩 1 个元素（i==j）循环不进——**候选答案没被检查就被丢弃**，承诺破产。诊断信号：WA 出现在"目标恰好在边界/单元素数组"的用例。

**坑 2：固定锚点 vs 动态锚点（153 旋转数组找最小值）。**
错版：`if nums[mid] > nums[0]` ——锚死在 `nums[0]`。事实：进入第二次收缩后，当前子问题**已经不是旋转数组**，`nums[0]` 与 mid 不在同一段单调区内，比较失去意义。修正：锚点必须跟当前子问题的边界走（`nums[hi]`），保证"和谁比"始终能判定 mid 落在哪一段。**一般化：二分的比较对象必须与被收缩的区间同步**。

**坑 3：搜索二维矩阵（074）的行列双折。**
矩阵不是"展平的二分"就是"逐行二分"——判别：`matrix[i][0] <= t <= matrix[i][n-1]` 的行单调性是否成立。074 行首严格递增 → 先二分行再二分列；240 行列双单调 → 走阶梯（右上角，每步排除一行或一列），**根本不是二分**。

### 7.2 分界：index space vs answer space

二分真正的分水岭不是"数组有序"，是**判决函数的单调性**：

| 类型 | 在什么上二分 | 判决函数 | 例 |
|---|---|---|---|
| index space | 下标 `[0, n)` | `nums[mid]` 与 target 的比较 | 704/34/33/153 |
| **answer space** | **答案的值域** `[min, max]` | `check(候选答案) 是否可行` | 875 吃蕉速度/1011 运力/410 分割最大和 |

answer space 的拆解套路（三步固定）：
1. 确定答案的值域 `[lo, hi]`（吃蕉速度 ∈ [1, max(piles)]）
2. 写单调裁决 `check(x)`：x 越大越容易可行（吃越快越省时间）——**单调性是二分的合法性证明，写 check 前先说清楚谁随谁单调**
3. 找"最小的可行 x"（或最大不可行）= 在单调布尔序列上找边界 = lowerBound 思想

**与回溯剪枝保真性同构**：砍掉一半的依据必须是"这半必无答案"——说不出来就不砍。

### 7.3 边界查找的不变量（34 查第一个/最后一个）

找第一个 `>= t`（lowerBound）：
```
承诺: [lo, hi] 内的答案: lo-1 左侧全 < t, hi+1 右侧全 >= t
mid 命中 → 答案可能是 mid, 但左边可能还有 → hi = mid (不 mid-1, mid 未排除!)
mid 未命中 → lo = mid + 1
终止时 lo == hi == 第一个 >= t 的位置
```
找最后一个（upperBound-1）对称。**收获信号：`hi = mid`（不带 +1）意味着 mid 是候选——这行写错 -1 就漏。**

### 7.4 操作清单（拿到题先问）

1. 在 index space 还是 answer space？后者先写 check 并证单调性
2. 比较锚点是否随区间收缩同步更新（153 教训）
3. 循环条件 `i <= j`，收缩必保不变量承诺
4. 递归写还是迭代写？迭代（栈深无忧，Go 尾调用无优化）
5. 溢出：`(lo+hi)/2` → `lo + (hi-lo)/2`（值域大时，如 410 的 sum 上界）
