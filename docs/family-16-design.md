# 家族 16：设计 —— 专题讲解

## 0. 速查卡（复习用）

- **信号**：实现一个数据结构，O(1) 或均摊 O(1) 的插入/删除/查找/随机
- **原语**：哈希+双向链表（LRU）、哈希+数组+交换删除（380）、哈希+堆（带过期）、前缀树（Trie）
- **锚点**：每个操作的最坏/均摊复杂度承诺 → 哪两个结构互补（各补各的短板）→ 双结构的一致性谁维护 → 随机性怎么保证等概率
- **失效**：要求最坏 O(1) 而哈希只给期望 → 平衡树/数组域换思路

## 1. 识别与反识别

**正信号**："设计并实现……使得 …… 操作的时间复杂度为 O(1)"。

**负样本对照**：

| 对比 | 分野 |
|---|---|
| 146 LRU vs 460 LFU（题单外） | LRU 淘汰"最久未用"（时间序，链表即可）；LFU 淘汰"最少使用"（频次序，需要频次桶+桶内时间）——**淘汰依据决定结构层数** |
| 380 O(1)插删+随机 vs 146 | 380 要随机访问 → 数组（下标随机）；146 要序维护 → 链表——**随机性逼数组，顺序性逼链表，两者都要就缝合** |
| 208 Trie vs 哈希集合 | 前缀查询（"有没有以 abc 开头的"）哈希前缀枚举 O(字符集^L) 死路——**前缀语义逼 Trie** |

## 2. 入门讲解

设计题的通用心法：**单个基本结构做不到的复杂度组合，用两个互补的结构缝合**——关键是找到"你的短板恰是我的长处"的一对。

**LRU（146）**：需要 O(1) 查找（哈希）+ O(1) 移动到头部/淘汰尾部（双向链表）。缝合方式：哈希的 value 存**链表节点指针**——查到即摸到节点，双向指针 O(1) 摘除重挂。头尾用 dummy 环（家族 6 的 dummy 思想双向版）。

**380 O(1) 三件套**：插入/删除/等概率随机获取。数组给随机（`rand.Intn(len)`）和尾插，但中间删 O(n)；哈希给 O(1) 定位但无随机。缝合：**删除 = 与尾元素交换后再 pop**——待删者挪到尾部，O(1) 落刀，哈希同步更新换位者的下标。这是"交换删除"原语的成名作。

**Trie（208）**：前缀的公共部分共享成路径。节点 = `children[26] + isEnd`。插入/查询沿字符逐层走。"abc 与 abd 只在最后分叉"的存储效率就是哈希集合给不了的**前缀结构**。

**一致性维护是设计题的真正考点**：两个结构各存一份信息（LRU 的 map 和链表、380 的 val→idx 和数组），每次操作必须**同步双写**——漏一处，结构间自相矛盾，bug 以"偶发错乱"的形态出现（最难查的一类）。

## 3. 原语库

| 原语 | 签名 | 前置条件 | 复杂度 |
|---|---|---|---|
| 哈希+双链 | `map[K]*Node` + 双向链表 | 查找 O(1) + 序操作 O(1) 的组合 | 各操作 O(1) |
| 交换删除 | `arr[i] = arr[last]; pop; m[v]=i 更新` | 允许打乱顺序 | 删除 O(1) |
| 等概率随机 | 数组 + `rand.Intn` | 元素无重复（或有计数） | O(1) |
| Trie | 节点数组子指针 + isEnd | 字符集有限 | 插/查 O(L) |
| 哨兵环 | head/tail 双 dummy 互指 | 链表边界统一 | — |

## 4. 思维锚点（含经典翻车模式，本族未开垦）

| # | 锚点问句 | 经典翻车（待本仓库实证） |
|---|---|---|
| 1 | **每个操作的复杂度承诺是最坏还是均摊？** | 均摊 O(1) 的结构（动态数组扩容）被当最坏承诺——面试官问"最坏多少"就穿帮 |
| 2 | **双结构的一致性在哪里同步？** | LRU 淘汰时只删链表忘删 map（或反之）：map 指向游离节点，下次命中读到幽灵——**每个变更点列出双写清单** |
| 3 | **交换删除后哈希更新了吗？** | 380 经典：换位者的新下标没写回 map，下一次删除删错人 |
| 4 | **随机获取要求等概率，元素重复吗？** | 元素可重复时"等概率取元素"与"等概率取值"不同——题面语义先行 |
| 5 | **链表的 dummy 环闭合了吗？** | head.prev = tail、tail.next = head 的环初始化漏一半，第一个真实节点插入后环断 |

## 5. 数学形式化

**双结构不变量**。

- **LRU**：任意时刻 `map[k] 指向的节点集合 == 链表节点集合`，且链表序 = 最近使用序。每操作后不变量保持（双写清单完备性）⟹ 任意时刻 get/put 语义正确
- **380**：`arr[0..n)` 无重复，`m[v]` = v 在 arr 的下标。交换删除保持两者 ⟹ `rand.Intn(n)` 均匀 ⟺ 每值等概率（数组域上的均匀分布）
- **证明义务**：设计题的正确性 = 不变量保持的逐操作验证——**"我没改错" 是定理不是感觉**

**等概率的形式化**：`rand.Intn(n)` 返回 i 的概率 1/n；arr 域上每值恰占一位 ⟹ 每值被取概率 1/n ∎。若值可重复，需要"值 → 下标集合"的均匀分配（每值 k 份则概率 k/n——与"每次取值等概率"语义不同，锚点 4）。

**均摊分析的适用**：动态数组 push 的均摊 O(1)（倍增扩容，总拷贝 ≤ 2n）；设计题把"偶发昂贵"摊到"平时廉价"——**均摊承诺必须能写出势能/聚簇论证**，写不出就不是均摊是运气。
