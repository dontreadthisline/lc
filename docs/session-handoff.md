## 用户工作风格（新 agent 必读）

- 用户在 **Neovim** 中实时编辑代码，经常写到一半保存。半成品会挡编译，agent 需要：临时替换为 TODO 壳（备份到 /tmp/），跑完测试后用户下次保存即恢复
- 用户**喜欢自己推导**，不喜欢直接看答案。agent 的角色是：给锚点问题、给方向提示、等用户卡住了再给下一步
- 用户会**主动报告完成**某题，agent 应立即检查（跑测试）并更新 INDEX
- 用户偶尔会用激烈的语气质疑 agent 的判断——**先验证再回应**，不要防御性辩解。用户的质疑有时是对的（本会话至少 3 次 agent 的初始判断被用户推翻）

## 刷题动线（核心流程）

```
读题面（mother-problems/题号-标题.md）
→ lc/题号.go 写实现（导出函数名，PascalCase）
→ lc_tests/题号_test.go：表驱动用例 + 暴力对拍（随机数据 2 万组）
→ 测试绿 → INDEX 打钩
→ 用户填思路列 → agent 评判
```

**状态规则**：
- `已完成` = 有通过测试的最优解
- `已完成（非最优）` = 测试通过但复杂度不达标（如 O(n³) 暴力）
- `做错` = 有实现但测试失败
- `未做` = 无实现或只有 TODO 桩

**注意**：测试覆盖率目前不完整（见"遗留问题"），不是所有已完成题都有独立测试。

## 本会话踩过的坑（新会话必读）

### Agent 侧
1. **函数名大小写**：用户写小写，测试调不到。检查前先 `grep '^func [A-Z]'`
2. **半成品挡编译**：停车 → 跑测试 → 用户保存恢复
3. **死循环测试**：跑测试必须带 `-timeout`。注意挂起可能不在被测算法里，而在错误报告路径（如带环结构体被 %v 打印）
4. **凭记忆写题面**：会编错。题面必须实时抓取或从文件读
5. **测试数据写错**：期望值/生成器越界。对拍双向无免检
6. **LCA"语义过载"**：标准解法返回值有多重含义。我给的"干净版"反而漏了祖先 case
7. **全量测试结果有挂起时不可信**：失败清单被 panic 输出吞掉
8. **检查进度必须全量扫描 lc/**：不能只看 git diff。漏了 12 道用户已完成的题
9. **check_progress.py 函数映射 bug**：多题共文件时捡错主函数，需维护显式映射表

### 用户侧常见错误模式（教学参考）
1. **`i < j` vs `i <= j`**：出现 3 次。结论：永远 `i <= j`
2. **区间开闭从模板带**：不从题面读
3. **固定锚点 vs 动态锚点**：如 153 用 nums[0]，应跟当前子问题边界走
4. **递归返回值语义不明确**：如 124 把"单链"和"全局答案"混在一起
5. **Go 语法**：`range` 返回下标、`%` 负数、泛型堆实例化
