# 家族 6：链表 —— 专题讲解

## 0. 速查卡（复习用）

- **信号**：单链表 + 反转/找点/删点/判圈/合并；禁用额外数组
- **原语**：dummy 哨兵、反转三件套（pre/cur/next）、快慢指针三模式、Floyd 判圈两阶段
- **锚点**：dummy 起步吗（特判葬礼）→ 判 nil 的顺序（摸 Next 前先确认人活着）→ 保存后继再改指针 → 返回 dummy.Next
- **失效**：需要随机访问/倒序遍历 → 先转数组（题目允许时）

## 1. 识别与反识别

**正信号**：`*ListNode` 进 `*ListNode` 出；删/插/找/转/判圈。

**负样本对照**：

| 对比 | 分野 |
|---|---|
| 19 倒数第 N vs 876 中点 | 同是双指针：019 是**间距恒定**（倒数坐标由间距携带）；876 是**间距线性增长**（2:1 步速） |
| 141 判圈 vs 142 找入环点 | 判圈一阶段够（追上即有环）；找入环点必须二阶段（相遇点 ≠ 入口，见 §5 Floyd 定理） |
| 206 反转 vs 25 K组翻转 | 25 = 批量调用 206 + 组间接缝——模块化组装题，不是新指针技术 |

## 2. 入门讲解

链表的全部痛苦来自**单向指针**：改一步丢一步。三个习惯治愈九成：

1. **dummy 哨兵**：一切涉及"头可能变"的操作（删头、合并、插入）从 `dummy := &ListNode{Next: head}` 起步——head 退化成普通内部节点，删头/删中同一逻辑，特判消失（019 两遍版的 `if l == n` 分支就是被 dummy 埋葬的）
2. **先存后改**：反转的 `next := cur.Next` 必须先抄下来——`cur.Next = pre` 一执行，后继就丢了
3. **判 nil 先于摸 Next**：条件里访问谁的 `.Next`，谁的 `!= nil` 必须排在它左边（141 的实证）

**反转（206）**迭代版五行的语义：pre 是"已反转部分的头"，cur 是"未处理部分的头"，每轮把 cur 摘一个挂到 pre 上。递归版是同一语义的栈式表达，但边界条件更脆（本仓库实证：递归版在尾节点 `tail.Next = head` panic，迭代版初版 `return cur` 在循环结束时恰是 nil——详见锚点表）。

**快慢指针三模式**（间距视角统一）：

| 模式 | 步速 | 间距行为 | 用途 |
|---|---|---|---|
| 恒定 | 1:1 | n+1 不变 | 019：倒数第 N 的前驱 |
| 增长 | 2:1 | 每轮 +1 | 876：中点（fast 到尾时 slow 走了一半） |
| 追赶 | 2:1 于环内 | 环内每轮 −1 | 141：环长步内必相遇 |

**Floyd 判圈二阶段（142）**：相遇不是终点。设 head 到入口 a 步、入口到相遇点 b 步、环长 c，则 `a + b = k·c`（fast 多走的都是整圈）⟹ 从相遇点再走 a 步恰好绕整数圈回到入口——一个指针掷回 head，两个同步一步走，再相遇即入口（完整推导见下 §5）。

## 3. 原语库

| 原语 | 签名 | 前置条件 | 复杂度 |
|---|---|---|---|
| dummy 遍历 | `dummy := &ListNode{Next: head}`，返回 `dummy.Next` | 头可能变的一切操作 | O(1) 额外 |
| 迭代反转 | pre/cur/next 三变量 | — | O(n) |
| 快慢找中点 | fast 2 步 slow 1 步；偶数长返回后中 | — | O(n) |
| 间距双指针 | fast 预走 n+1，同步走到 nil | 从 dummy 起步 | O(n) |
| 判圈 | 快慢相遇 ⟺ 有环 | 判 nil 顺序正确 | O(n) |
| 找入环点 | 相遇后一指针回 head，同步一步再相遇 | 判圈已成立 | O(n) |
| 哈希判圈/找交点 | `map[*ListNode]struct{}` 走过即记 | 允许 O(n) 空间 | O(n) 时间 O(n) 空间 |

## 4. 思维锚点（含本仓库实证）

| # | 锚点问句 | 违反后果（实证） |
|---|---|---|
| 1 | **头会变吗？dummy 起步了吗？** | 019 两遍版删头特判 `if l == n` 活着时，删头用例连挂（单节点 panic、错删下一个）；dummy 后特判整个消失 |
| 2 | **条件里摸谁的 Next，谁的非 nil 检查排在左边了吗？** | 141 修复实录：判了 `slow != nil` 没判 `fast != nil`——fast 跳两步先越界，`fast.Next` 摸了 nil 的 Next。危险不在比较处，在**条件求值处** |
| 3 | **改指针前，后继存了吗？** | 经典丢失：`cur.Next = pre` 之前不抄 `next`，后半条链蒸发（025/143 类操作的高发点） |
| 4 | **反转的递归版，链尾的 tail 是 nil 吗？** | 206 实证：递归版对最后一个节点执行 `tail.Next = head`，而 tail == nil → panic——**任何输入都炸**；迭代版 `return cur` 在循环结束时 cur 恒为 nil，返回空链 |
| 5 | **删除操作停在前驱还是目标上？** | 019 一遍版实证：unlink 写在扫描前，slow 还站在 dummy，每次都删头——**删除时机在扫描后**（slow 停稳才动手） |
| 6 | **双计数器循环里，每个下标跟自己的坐标系走？** | 238 教训的链表版预警：左右两个游标同屏时，操作两侧各自用各自的变量 |
| 7 | **死循环排查：环内指针前进失效了吗？** | 142 实证：快慢版在带环输入上死循环挂死测试进程——环上代码的 bug 不 panic、不返回，就是转；跑测试必带 `-timeout` |

## 5. 数学形式化

**Floyd 判圈定理**。设 head→入口 a 步，入口→相遇点（沿前进方向）b 步，环长 c。

- **命题 1（必相遇）**：slow 进环后，每轮 fast 与 slow 的间距缩短 1，至多 c 轮相遇
- **命题 2（二阶段定位）**：相遇时 slow 走 `a+b`，fast 走 `2(a+b)`，差值 `a+b` 全部用于套圈 ⟹ `a + b = k·c`（k ≥ 1）。从相遇点走 a 步：`b + a = k·c ≡ 0 (mod c)`，即整数圈回到入口；而 a 步之前，head 侧指针仍在尾巴（不在环内），两指针分属不相交的节点集，不会提前相遇 ⟹ 再相遇点恰为入口 ∎
- **假设**：环存在（否则第一阶段 fast 先触 nil）；步速严格 2:1
- **推论**：相遇点 = 入口 ⟺ `a ≡ 0 (mod c)`（特例：a=0，头即入口）——"相遇点大概率不在入口"的精确表述

**间距不变量（双指针三模式）**：恒定模式 `pos(fast) − pos(slow) = n+1` 在 lockstep 下守恒，fast 触 nil 时翻译为"slow 距尾 n+1 = 目标前驱"——**相对位置编码绝对位置未知的信息**，与家族 2 滑窗同源。

**反转的循环不变量**：任意时刻，pre..（反向链） 与 cur..（原向剩余链） 拼接 == 原链的所有节点。归纳保此不变量，终止时 pre 即反转头 ∎。

## 6. 迁移与连接

- 哈希判圈/找交点是家族 1（集合查存在）在指针域的直译——时间 O(n) 换空间 O(n)，快慢指针是无空间版
- 143 重排 = 找中点（876）+ 反转后半（206）+ 归并（21）三原语组装
- LRU（家族 16）= 哈希 + 双向链表，dummy 思想的双向升级
