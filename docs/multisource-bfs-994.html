核心论证：BFS 循环体对「队列内容的来历」一无所知

单源 BFS 与多源 BFS 的全部区别，就是队列的初始内容。循环体（出队 → 查四邻 → 入队）一个字都不用改。
  1. BFS 的不变量：任意时刻，队列里的元素都位于「同一距离层」（至多跨相邻两层）。初始入队 {s} 意味着宣告「距离为 0 的点 = {s}」；初始入队 {s1…sk} 意味着宣告「距离为 0 的点 = 源集合」。之后每一轮扩散都严格把距离 +1，这个性质与第 0 层有几个点毫无关系。
  2. 循环体无来源感知：出队 → 检查四邻是否为 1 → 标 2 → 入队 这组操作从不关心出队元素是「原始腐烂源」还是「刚被感染的橘子」。第 0 层是 1 个点还是 50 个点，操作完全相同。
  3. 答案语义 = min 距离：橘子 v 的腐烂时刻 = mini dist(si, v)（离哪个源近就听谁的）。BFS 按距离升序逐层扩张，第一次触达 v 的层号恰好就是这个 min。起点从一个变成多个，「按距离升序扩张」的性质不变，正确性不变。
  4. 时间复杂度仍是 O(mn)：每个格子至多入队一次、出队一次。多源不是「跑 k 遍单源」（那是 O(k·mn)），而是所有源合起来当第 0 层，一遍扫完。
常见误区：「多源 = 对每个源各跑一遍单源 BFS 再取 min」。能得到正确答案，但浪费：格子会被重复访问。正确做法是把 min 的语义直接折叠进初始队列——这正是「把起点都加入队列」的本质。

超级源点归约：多源 BFS 严格等价于一次单源 BFS

构造一个虚拟节点 S，从 S 向每个腐烂源连一条零长边。那么：

  • 在扩展图上从 S 跑标准单源 BFS：第一层扩散把 s1、s2、s3 全部入队（零长边，同为距离 1）。
  • 删掉 S、直接把 s1、s2、s3 当作初始队列——从第二层起两种执行逐帧相同。
  • 所以：多源 BFS 不需要任何新算法，只需把「第 0 层」从 {s} 换成 {s1…sk}。对照上方动画勾选「单源对照」，直观感受第 0 层选错（漏掉源）的后果。

三个经典翻车点（都用测试用例钉死了）

翻车 1：新感染者不入队

格子标了 2 却没有 queue = append(queue, ...)。BFS 只活一层：第 1 分钟后队列空了，远处的新鲜橘子再也等不到波。

测试：[[2,2,1],[2,1,0],[0,1,1]] 会错误地返回 -1（明明可达）。

翻车 2：每层无条件 minute++

最后一层只是把队列清空，没有任何橘子腐烂，这一分钟不存在。

测试：[[2]] 会错误地返回 1，正确答案是 0。解法就是动画里的 rotted 标记——本轮真的感染了东西才计时。

翻车 3：忘记不可达检查

队列跑完不等于全部腐烂。用 感染数 cnt 与初始新鲜数 fresh 对账，或扫一遍网格还有没有 1，有则返回 -1。

测试：[[2,1,1],[0,1,1],[1,0,1]] 左下角被隔死，正确答案是 -1。

三个翻车点分别对应算法的三个部位：接棒（入队）、计时（层语义）、对账（终止条件）。多源反而是最不容易错的部分——它只是初始化。
