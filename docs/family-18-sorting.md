# 家族 18：排序与杂项 —— 专题讲解

## 0. 速查卡（复习用）

- **信号**：手写排序（禁用库）；自定义比较规则（"拼起来最大/最小"）
- **原语**：快排 partition、归并 merge、自定义全序比较器
- **锚点**：比较器是**全序**吗（传递性！）→ 快排的基准选择与退化 → 归并的稳定性能不能要 → 比较器与等价性（相等元素的处理）
- **失效**：比较器不传递 → 排序结果未定义；近乎有序数据 + 固定基准快排 → O(n²)

## 1. 识别与反识别

**正信号**："不许使用内置排序"；"按 xx 规则重排使结果最大/最小"。

**负样本对照**：

| 对比 | 分野 |
|---|---|
| 912 排序数组 vs 179 最大数 | 912 考**排序的实现**（快排/归并）；179 考**比较器的构造**（拼接序）——一考怎么排，一考按什么排 |
| 179 拼接序 vs 数值序 | "3 和 30 谁在前"数值序无解——`"330" vs "303"` 的字典序才是正确序——**自定义全序的构造题** |
| 快排 vs 归并 | 原地 + 平均快（快排）；稳定 + 最坏 O(n log n)（归并）——要求"最坏保证"选归并，见 §5 反例 |

## 2. 入门讲解

**手写快排（912）**：partition 是灵魂——选基准，一遍扫描把数组切成"≤ 基准 | 基准 | ≥ 基准"，递归两侧。partition 的正确性证明与边界细节见 `docs/quickselect-partition-proof.md`（同款 partition 支撑快速选择 Top-K）。

**退化与对策**：固定取首元素做基准，近乎有序的输入每次只切掉一个 → O(n²)。对策：随机基准（期望 O(n log n)，证明依赖随机化的期望分析）或三数取中。

**归并**：分半递归 + 线性合并。**稳定性**来自合并时"相等取左半"——快排的远距离交换破坏稳定性，需要稳定时归并是唯一主流选择。

**自定义比较器（179）**：两个数 a、b 谁 active 在前？判定标准：拼出 `ab` 与 `ba`，字典序大者在前。这不是天然序，是**构造出来的全序**——它的传递性需要证明（§5），不证明的拼 `sort.Slice` 可能得到未定义结果。

**全序四公理**（写比较器的验收清单）：反对称、传递、完全性、（自反用于等价）。**传递性是自定义比较器最容易违反的一条**，也是违反后最难察觉的（小样例全对，大数据偶发错乱）。

## 3. 原语库

| 原语 | 签名 | 前置条件 | 复杂度 |
|---|---|---|---|
| partition | 选基准一遍切分，返回基准落位 | 见证明文档 | O(n) |
| 快排 | partition + 两侧递归 | 随机/取中基准防退化 | 平均 O(n log n)，最坏 O(n²) |
| 归并 | 分半 + 稳定合并 | 需要稳定或最坏保证 | 最坏 O(n log n)，空间 O(n) |
| 自定义比较器 | `less(a,b) bool`，须构成全序 | 传递性已证 | — |
| 拼接序 | `ab > ba ⟹ a 在前` | 字符串拼接比较 | O(总位数 log n) |

## 4. 思维锚点（含经典翻车模式，本族未开垦）

| # | 锚点问句 | 经典翻车（待本仓库实证） |
|---|---|---|
| 1 | **比较器传递性证了吗？** | 拼接序直接上 `sort.Slice`：传递性是定理（§5），不证就信 = 在未定义行为上盖楼——长度不等/前缀相等的对是证传递性的关键例 |
| 2 | **全零输入处理了吗？** | 179 经典：`[0,0]` 拼出 `"00"`，答案应为 `"0"`——拼接后的去零边界 |
| 3 | **基准怎么选？** | 固定首元素 + 有序数据 = O(n²) 退化；随机基准的期望分析是标准配菜 |
| 4 | **稳定性能不能丢？** | 快排交换远距元素：相等键的相对序被打乱——下游逻辑依赖相等序时（多关键字排序的第二阶段）必须归并 |
| 5 | **比较器返回 bool 还是 int？** | `less` 三态语义（<,=,>）压成 bool 后等价类的处理交给库——等价元素交换与否影响稳定性 |

## 5. 数学形式化

**拼接序的全序性（179 的核心定理）**。

- **命题**：定义 $a \preceq b \iff ab \geq ba$（字符串拼接字典序），则 $\preceq$ 是全序
- **证明（传递性， hardest 部分）**：设 $a \preceq b$ 且 $b \preceq c$，即 $ab \geq ba$、$bc \geq cb$。把字符串看作大整数：$ab = a \cdot 10^{|b|} + b$。$ab \geq ba \iff a(10^{|b|} - 1) \geq b(10^{|a|} - 1)$（移项整理）。记 $\nu(x) = x / (10^{|x|} - 1)$，条件化为 $\nu(a) \geq \nu(b)$，同理 $\nu(b) \geq \nu(c)$，故 $\nu(a) \geq \nu(c)$ ⟹ $ac \geq ca$ ⟹ $a \preceq c$ ∎
- **直观**：每个数字有一个内在"权重" $\nu$，拼接序就是按 $\nu$ 降序——**比较器背后藏着数值势函数**是自定义序可证的常见形态
- **反例（不构造全序的代价）**：按 `int(a) > int(b)` 排 `[3, 30]`：数值序 30 > 3，得 `"303"`；正确是 `"330"`——天然序在这个问题域上根本不是序

**快排的期望复杂度**：随机基准下，每对元素至多比较一次的概率论证 → 期望比较次数 $O(n \log n)$（熵论证：每个元素成为"分隔者"的机会均等）。**最坏 O(n²) 真实存在**（构造性反例：基准总落在边缘）。

**归并的稳定性定理**：合并时左半优先 ⟹ 相等元素的原始相对序保持——归纳于合并层数 ∎。

**partition 正确性**：见 `docs/quickselect-partition-proof.md`（循环不变量 + 边界的三种写法对照）。
