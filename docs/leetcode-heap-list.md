配套代码：`algo/genericheap.go`（自包含泛型堆）。题号前标 [验] 的共 24 道，链接当场核验；其余 8 道为超经典题（23/215/295 等）记忆整理，题号若对不上以标题搜索为准。

## 先立核心认知：堆在算法题里的四大角色

| 角色 | 一句话 | 堆顶的语义 |
|---|---|---|
| **Top-K** | 流式/海量数据里维护"最大的 K 个" | 堆顶是**门槛**（K 个里最差的那个） |
| **多路归并** | K 个有序序列合成一个 | 堆顶是"当前各路出头者中最小的" |
| **双堆** | 动态维护中位数/分位数 | 两堆顶夹着答案 |
| **反悔贪心** | 贪心走错了能反悔 | 弹出堆顶 = 撤销一次决策 |

最反直觉也最重要的一条：**求第 K 大，用小顶堆**（堆顶是那 K 个最大元素里最小的，正好是门槛）；求第 K 小，用大顶堆。堆顶永远不是答案的方向，是**门槛的方向**。

## 阶段 3 双堆与数据结构设计

| 题目 | 难度 | 考点 |
|---|---|---|
| 295. 数据流的中位数 | 困难 | 双堆教科书题：大顶堆装左半、小顶堆装右半 |
| 480. 滑动窗口中位数 [验] | 困难 | 295 + 窗口滑出删除——**Remove 与惰性删除的正面对决场** |
| 2034. 股票价格波动 [验] | 中等 | 哈希定位 + 堆取极值；更新走 Fix/惰性两种思路 |
| 2349. 设计数字容器系统 [验] | 中等 | 哈希索引 + 每键一个小顶堆（惰性删除防重） |
| 2402. 会议室 III [验] | 困难 | 双堆模拟（空闲/占用），经典系统设计题 |

**模型**：中位数 = 左大顶 + 右小顶，平衡条件 |left|-|right| ≤ 1。窗口滑出元素时两条路：`Remove(i)` 精确删（需要索引追踪，正是 genericheap 外科手术接口的用武之地），或惰性删除（打标记，堆顶弹到过期条目跳过——Dijkstra 同款，代价是堆内有垃圾）。

## 刷题建议

1. **顺序即依赖**：0 → 1 → 2 是基本功；3 开始出现 Remove/惰性删除的取舍；4、5 是堆与其他思想的组合
2. **每组对照刷**：215 三解对照；264 vs 313（DP 指针 vs 堆）；295 vs 480（纯 Push/Pop vs 删除语义）；857 vs 1383（同骨架）
3. **拿 genericheap 当练兵场**：全部题目都可以不用 `container/heap` 而用 `NewHeap(func(a, b T) bool {...})` 写——比较器注入正好覆盖各题定制序（692 的字典序、1834 的多级序），480 专门用 `Remove` 和惰性删除各写一遍，体会两个策略的真实代价
4. **配证明读**：`docs/heap-properties-proof.md`（堆序保持、Floyd O(n)）；215 配 `docs/quickselect-partition-proof.md`
