# 家族 1：哈希与集合 —— 专题讲解

## 0. 速查卡（复习用）

- **信号**：查找存在 / 配对 / 频次 / 分组；n ≥ 10⁶ 要 O(n)
- **原语**：`contains(x)` 查存在、`count[x]` 数重数、`groupBy(签名)` 分组、集合连续段遍历（只从段起点走）
- **锚点**：内层在查什么 → 键是谁（对方，不是自己）→ 要存在还是重数 → 先查后插
- **失效**：依赖顺序/大小关系的问题哈希接不住

## 1. 识别与反识别

**正信号**：题面出现"前面有没有 / 出现几次 / 哪些属于同一类"，且数据规模逼出 O(n)（复杂度反推表见 `docs/leetcode-8020-mother-problems.md` §2）。

**负样本对照**（分类能力靠对比练，不靠清单）：

| 对比 | 分野 |
|---|---|
| 001 两数之和 vs 560 和为K的子数组 | 元素配对用集合；**前缀**配对才需要前缀和换元——560 的数组含负数，滑窗也无资格 |
| 049 分组 vs 347 前K个高频 | 分组只要签名做键；"前 K"要动态取最值，那是堆的地盘（家族 14） |
| 128 连续序列 vs 子串问题 | 128 问"存在连续段"——集合的成员资格就是全部信息；连续**子串**的极值要窗口（家族 2） |

## 2. 入门讲解：从暴力到哈希

以 001 为例。暴力枚举所有对 `(i, j)` 检查 `a[i] + a[j] == target`，O(n²)。

关键一步是**读懂内层循环在干什么**：固定 j 时，内层在问——"我之前，有没有人等于 `target − a[j]`？"这是一个**查找**，且目标值 `t_j = target − a[j]` 在轮到 j 之前就能算出来。把"已见元素"放进集合，每轮 O(1) 查询：

```
j 从左到右：
    查：t_j 在不在集合里？在 → 找到配对
    插：把 a[j] 放进集合
```

**先查后插**保证配对方严格在左边（`i < j`），并天然排除自己配自己。

049 把查找升级成分组：异位词的共性是字母计数相同——定义**签名函数**（排序串 O(L log L) 通用，或 26 维计数串 O(L) 依赖字母表有限），签名做键一遍收集。

128 是配对思想的变奏：数组入集合后，连续段信息编码在**成员资格**里；只从"段起点"（`x−1` 不在集合中的 x）向后走，每段完整走一遍。

## 3. 原语库

| 原语 | 签名 | 前置条件 | 复杂度 |
|---|---|---|---|
| 查存在 | `seen map[T]struct{}`，先查后插 | 配对方可由己方值 O(1) 解出 | 期望 O(n) |
| 数重数 | `m map[T]int`，`res += m[t_j]` 后 `m[a_j]++` | 同上；要的是"多少对"不是"有没有" | 期望 O(n) |
| 签名分组 | `groupBy(key(T) K) map[K][]T` | 存在等价类划分函数 key | O(n·L) |
| 连续段遍历 | 集合中只从 `x−1 ∉ S` 的 x 起走 | 值域是整数（可 ±1 探测） | 摊还 O(n) |

## 4. 思维锚点（含本仓库实证）

| # | 锚点问句 | 违反后果（实证） |
|---|---|---|
| 1 | **内层循环在查什么？** 查存在→集合；数个数→计数器；分组→签名做键 | 拿集合做计数题：001 的写法搬去 560，重数全丢——"有没有"和"有几个"是两种 value 类型 |
| 2 | **键是谁？** 键 = 对方的值，用我的值表示（`target − a[j]`），不是我自己 | 键写成自己：查的是"我"不是"对手"，永远查不到配对方（家族 3 的 560 键方向错，同一根神经） |
| 3 | **要存在性还是重数？** | value 用 `struct{}` 装"存在"，计数题直接丢答案 |
| 4 | **顺序重要吗？** 哈希无序 | 依赖顺序（最近、滑动、栈序）的题哈希单独接不住，需要它配合别的结构 |
| 5 | **先查后插了吗？** | 先插后查：k=0/自配条件成立时自己配自己，多数出空对 |
| 6 | **集合遍历题：谁有资格当起点？** | 128 翻车版：用成员资格判断替代"段起点判定"，`Hash([1,2,2,3])=4`——重复元素被段内重数。起点资格必须是"`x−1` 不在集合中" |

## 5. 数学形式化

**配对计数定理**。目标数 $|\{(i,j) : i < j,\ C(a_i, a_j)\}|$，C 为 O(1) 可判定关系。流式维护 $M_j = \{a_0..a_{j-1}\}$，第 j 轮增量 $\Delta_j = |\{x \in M_j : x = t_j\}|$，$t_j = \tau(a_j)$ 由 C 解出。

- **证明（双射）**：满足 C 的每个对在其右端点轮恰被数一次；不满足的永不被数 ∎
- **假设**：① τ 可 O(1) 计算；② 哈希单次期望 O(1)
- **违反假设的反例**：C 是"大于某值"时 τ 无单值解（不等式配对）——哈希只会等值匹配，升级为有序结构（树状数组，见家族 3 失效连接）

**连续段遍历的摊还定理**。

- **命题**：只从段起点走，总步数 = 各极大段长之和 ≤ n，总 O(n)
- **假设**：每个元素仅作为"某一段的成员"被走一次，起点判定 O(1)
- **反例（违反"只从起点走"）**：从每个元素都走一遍，全连续输入退化为 $1+2+\cdots+n = O(n^2)$——这正是锚点 6 那次翻车的数学本质

**复杂度的诚实**：哈希是**期望** O(1)、最坏 O(n)（全碰撞）；需要最坏界或有序遍历时换平衡树（O(log n)）。
